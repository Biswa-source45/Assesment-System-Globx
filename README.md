# GLOBX Assess - Online Assessment Platform (MVP v2.1)

A HackerEarth / HackerRank-class assessment platform built to the GLOBX SRS v2.1 (the SRS document is kept locally, not in git).
One Python process serves the web app, the REST API and the code sandboxes; data lives in PostgreSQL.
Production will run in Docker (app + database); there is no Docker setup yet.

## Local development

```bash
# 1. database: create "oap" in your local PostgreSQL, then put this in .env (repo root)
#    DATABASE_URL=postgresql+psycopg://USER:PASSWORD@localhost:5433/oap
#    SECRET_KEY=<any long random string>
# 2. backend
cd backend
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python -m app.seed                                   # tables + demo data
.venv/Scripts/python -m uvicorn app.main:app --port 8000 --reload  # http://localhost:8000/api/docs
```

Demo logins (staff and candidates) are generated by the seed with random passwords and written to `backend/data/seeded_accounts.txt` (git-ignored).

## What is implemented

| Area | MVP implementation |
|---|---|
| Question types | MCQ single, MCQ multiple (partial scoring + over-selection rule), **Linked MCQ** sets (2 marks / -0.5), Short answer (2), Long answer (5, rubric), Programming (10, 3 open + 3 hidden weighted 1+1+1+2+2+3), **SQL** (10, 3 + 3 datasets) |
| Sandboxes (no Docker) | One class per language: **Python, C, C++, Java, JavaScript** + **SQL (SQLite always; PostgreSQL / MySQL optional)**. Limits: CPU, wall-clock, memory (process-tree RSS), output, scrubbed env, throw-away work dir, tree kill; Linux also gets rlimits + network isolation (`unshare -rn`). Verdicts AC/WA/TLE/MLE/RE/CE/OLE/IE. Async judge queue (threads) |
| Authoring | Reusable library, groups, bulk MCQ import (CSV/XLSX), reference-solution validation, versioning, sections with timers / lock navigation / min score, random **pools** with difficulty mix, publish validation |
| Candidate | Email OTP login, invite links, dashboard, practice test, system check (browser, camera, mic, network, displays, VM), consent, runner with section tabs, palette, mark for review, autosave + resume, server-authoritative timer, auto-submit, code IDE with Run/Submit/custom input, SQL IDE with result grid, rich-text answers, file upload, result + feedback |
| Proctoring | Webcam snapshots (FaceDetector / optional OpenCV face count), tab/focus/fullscreen/copy-paste/devtools events, voice activity, multi-display block, VM flag, optional screen screenshots, weighted risk score Low/Medium/High/Critical, violation limit -> auto-submit |
| Grading | Automatic for MCQ/coding/SQL; short = keyword 40% + AI semantic 60%; long = AI rubric suggestion + mandatory evaluator; blind review queue with override reason; cut-off, section minimums, ranking |
| Plagiarism | Every pair of answers per question: winnowing fingerprints (code/SQL, identifiers normalised, starter code excluded) and 5-gram overlap (text); High >= 85%; side-by-side compare; decisions; adds risk |
| Reports | Candidate report (sections vs average, proctoring observations, snapshots, timeline, code, plagiarism), test analytics (funnel, distribution, integrity, languages, question health), CSV/XLSX export |
| Admin | Users and roles (multi-role), organisations, sandbox status + self-test, audit log, mail outbox, TOTP 2FA, account lockout |
| AI (optional) | `LLM_PROVIDER` = none, ollama, openai, azure_openai, gemini, claude |

Not in this MVP (SRS Phase 2 / Enterprise): Docker/gVisor isolation, face *matching* against an ID photo, lockdown browser, SSO/ATS, live interviews, video answers.

## Repository layout

```
online-assessment-platform/
├── .env.example              all settings (copy to .env)
├── backend/
│   ├── app/
│   │   ├── main.py           FastAPI app, serves frontend/dist
│   │   ├── core/             config, security (scrypt, JWT, TOTP), dependencies / RBAC / audit
│   │   ├── models.py         SQLAlchemy models (UUID keys, decimal marks)
│   │   ├── domain/           pure rules: scoring, risk, plagiarism (unit tested)
│   │   ├── sandbox/          process limits, per-language sandboxes, SQL engines, judge, self-test
│   │   ├── services/         attempts & grading, jobs (queue + sweeper), proctoring, plagiarism, invites, reports, mail, AI
│   │   ├── api/              auth, library, tests, candidate, staff routers (/api/v1, docs at /api/docs)
│   │   └── seed.py           demo organisation, users, 21 questions, sample + practice tests
│   ├── tests/                pytest: scoring, risk, plagiarism, every sandbox, full API flow
│   └── requirements.txt
└── frontend/
    └── src/                  React + JSX (JavaScript, no TypeScript), Vite, Tailwind, shadcn/ui; `npm run build` writes dist/ (git-ignored)
```

## Development

```bash
# backend tests
backend/.venv/Scripts/python -m pytest backend/tests      # Windows
# browser tests (own API on :8001 + throw-away oap_test DB; RUN_AI=1 adds the real OpenAI call)
cd frontend && npx playwright test
# frontend - needs Node.js 18+
cd frontend && npm install && npm run dev                  # http://localhost:5173 (proxies /api to :8000); `npm run build` for dist/
# API explorer
http://localhost:8000/api/docs
```
