# KAUTILYA by GLOBX - Intelligent Assessment Platform (MVP v2.1)

A HackerEarth / HackerRank-class assessment platform built to the GLOBX SRS v2.1 (the SRS document is kept locally, not in git).
One Python process serves the web app, the REST API and the code sandboxes; data lives in PostgreSQL.
Production will run in Docker (app + database); there is no Docker setup yet.

## Local development

```bash
# 1. database: create "oap" in your local PostgreSQL, then put this in .env (repo root)
#    DATABASE_URL=postgresql+psycopg://USER:PASSWORD@localhost:5433/oap
#    SECRET_KEY=<any long random string>
# 2. backend
cd backend
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python -m app.seed                                   # applies migrations + demo data (--reset wipes first)
.venv/Scripts/python -m uvicorn app.main:app --port 8000 --reload  # http://localhost:8000/api/docs
```

Demo logins (staff and candidates) are generated by the seed with random passwords and written to `backend/data/seeded_accounts.txt` (git-ignored).

## What is implemented

| Area | MVP implementation |
|---|---|
| Question types | MCQ single, MCQ multiple (strict: right options share the marks, each wrong option ticked takes 0.25 off, never below 0, ticking every option scores 0), **Linked MCQ** sets (2 marks / -0.5), Short answer (2), Long answer (5, rubric), Programming (10, 3 open + 3 hidden weighted 1+1+1+2+2+3), **SQL** (10, 3 + 3 datasets) |
| Sandboxes | In production all candidate code runs in the isolated judge container (`Dockerfile.judge`, `docker-compose.yml`; see DEPLOYMENT.md section 3). One class per language: **Python, C, C++, Java, JavaScript** + **SQL (SQLite always; PostgreSQL / MySQL optional)**. Limits: CPU, wall-clock, memory (process-tree RSS), output, scrubbed env, throw-away work dir, tree kill; Linux also gets rlimits + network isolation (`unshare -rn`). Verdicts AC/WA/TLE/MLE/RE/CE/OLE/IE. Async judge queue (threads) |
| Authoring | **Build an exam from AI-made JSON** (the app writes the prompt from the exam's details and the counts you ask for; you upload the JSON; it is checked as a whole, then imported), reusable library, groups, bulk MCQ import (CSV/XLSX), reference-solution validation, versioning, sections with timers / lock navigation / min score, random **pools** with difficulty mix, publish validation |
| Candidate | Email OTP login, invite links, dashboard, practice test, system check (browser, camera, mic, network, displays, VM), consent, runner with section tabs, palette, mark for review, autosave + resume, server-authoritative timer, minimum reading time per question (Next stays locked for a few seconds), auto-submit, code IDE with Run/Submit/custom input, SQL IDE with result grid, rich-text answers, file upload, result + feedback |
| Evidence (per exam) | **Pictures** (camera every N s, screen every M s, plus a picture at every incident) **or video of the whole exam** (camera and screen, sent in 10-second pieces, **deleted automatically after 14 days**, editable); the candidate shares the entire screen (stopping counts like leaving the window); **live view** of every camera and screen in the Live monitor, text messages and a private two-way voice line to one candidate (WebRTC, the server only relays the connection messages) |
| Proctoring | Webcam snapshots (FaceDetector / optional OpenCV face count), tab/focus/fullscreen/copy-paste/devtools events, voice activity, multi-display block, VM flag, optional screen screenshots, weighted risk score Low/Medium/High/Critical, violation limit -> auto-submit |
| Grading | MCQ by formula and coding/SQL by weighted test cases (no AI); short = keyword 40% + AI semantic 60%, explained = AI rubric, **only after the exam's end time**, once per answer; an AI mark counts at once when it is sure, otherwise it waits for a person; overrides need a reason; cut-off, section minimums, ranking |
| Results | Calculated per exam automatically after its end time (or by a button when there is no end time); people who did not attend and people whose exam was ended are recorded; review each candidate (answers, AI reasoning, code verdicts, proctoring timeline and pictures); accept AI marks; **declare** to the candidates; CSV/XLSX export |
| Plagiarism | Every pair of answers per question: winnowing fingerprints (code/SQL, identifiers normalised, starter code excluded) and 5-gram overlap (text); High >= 85%; side-by-side compare; decisions; adds risk |
| Reports | Candidate report (sections vs average, proctoring observations, snapshots, timeline, code, plagiarism), test analytics (funnel, distribution, integrity, languages, question health), CSV/XLSX export |
| Admin | Users and roles (multi-role), organisations, sandbox status + self-test, audit log, mail outbox, TOTP 2FA, account lockout |
| AI (optional) | `LLM_PROVIDER` = none, ollama, openai, azure_openai, gemini, claude |

Not in this MVP (SRS Phase 2 / Enterprise): Docker/gVisor isolation, face *matching* against an ID photo, lockdown browser, SSO/ATS, live interviews, video answers.

## Roles and permissions

Enforced by the server (`backend/app/core/deps.py`, `ROLE_GROUPS`); the browser gets the same answers from `/auth/me` (`can`), so each screen shows only what the person may use. A Super Admin passes every check.

| Action | Super Admin | Org Admin | Test Creator | Recruiter | Evaluator |
|---|:-:|:-:|:-:|:-:|:-:|
| See exams, candidates, reports; watch the live monitor | yes | yes | yes | yes | yes |
| Create, edit and publish exams; build with AI; auto populate | yes | yes | yes | - | - |
| Create and edit questions, departments | yes | yes | yes | - | - |
| Read the question bank (answer keys included) | yes | yes | yes | - | yes |
| Add participants and logins; extend, end, re-open an exam; export | yes | yes | yes | yes | - |
| Mark answers, override AI marks | yes | yes | - | - | yes |
| Users (add, edit roles, change password, disable, unlock), audit log | yes | yes | - | - | - |
| Grant or change a Super Admin; organisations | yes | - | - | - | - |

Candidates can do none of the above: they only open and answer the exams given to them.

## Repository layout

```
online-assessment-platform/
├── .env.example              all settings (copy to .env)
├── user-assets/              camera pictures and uploaded answer files of real exams (git-ignored; back it up with the database)
├── backend/
│   ├── app/
│   │   ├── main.py           FastAPI app, serves frontend/dist
│   │   ├── core/             config, security (scrypt, JWT, TOTP), dependencies / RBAC / audit
│   │   ├── models.py         SQLAlchemy models (UUID keys, decimal marks)
│   │   ├── domain/           pure rules: scoring, risk, plagiarism (unit tested)
│   │   ├── sandbox/          process limits, per-language sandboxes, SQL engines, judge, self-test
│   │   ├── services/         attempts & grading, jobs (queue + sweeper), proctoring, plagiarism, invites, reports, mail, AI
│   │   ├── api/              auth, departments, library, tests, exam_pack, results, live (WebSocket, video upload), candidate, staff routers (/api/v1, docs at /api/docs)
│   │   └── seed.py           demo organisation, departments, users, about 34 questions, sample + practice tests
│   ├── migrations/           Alembic: the app upgrades the database on start; after editing models.py run `alembic revision --autogenerate -m "what changed"`
│   ├── tests/                pytest: scoring, risk, plagiarism, every sandbox, full API flow
│   └── requirements.txt
└── frontend/
    └── src/                  React + JSX (JavaScript, no TypeScript), Vite, Tailwind, shadcn/ui; `npm run build` writes dist/ (git-ignored)
```

## Development

```bash
# backend tests
backend/.venv/Scripts/python -m pytest backend/tests      # Windows
# browser tests (own API on :8001 + throw-away oap_test DB; RUN_AI=1 adds the real OpenAI call)
cd frontend && npx playwright test
# frontend - needs Node.js 18+
cd frontend && npm install && npm run dev                  # http://localhost:5173 (proxies /api to :8000); `npm run build` for dist/
# API explorer
http://localhost:8000/api/docs
```
